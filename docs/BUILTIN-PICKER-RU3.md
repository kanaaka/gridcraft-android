# Встроенный выбор файлов и русский интерфейс — files-ru.3

Меню «Открыть» использует исходное окно egui. Вызовы системного выбора документов
удалены из Java и Rust. Открытие из этого окна передаёт движку исходный путь:
обычное сохранение относится к исходному файлу.

Фильтр перечисляет все поддерживаемые расширения: `xlsx`, `xlsm`, `xltx`, `xltm`,
`xls`, `xlt`, `xlsb`, `ods`, `csv`, `tsv`, `tab`, `txt`, `json`, `scjson`.
Регистр расширения и кириллица в имени не меняют результат. В окне показан список
форматов и число подходящих файлов; «Показать все файлы» позволяет отключить фильтр.

При первом открытии выбирается папка с подходящими документами, затем «Загрузки»;
пустая папка «Документы» больше не является безусловным начальным местом.
Последняя открытая папка запоминается в пределах окна приложения.

Для прямого просмотра общей памяти Android 11+ нужен «Доступ ко всем файлам».
На Android 10 проверяется одновременно READ_EXTERNAL_STORAGE и фактический legacy
режим. Одного успешного read_dir недостаточно: при scoped storage документы могут
скрываться. Неразрешённые общие папки показаны закрытыми, с кнопкой настройки доступа.

Для файловых менеджеров зарегистрированы VIEW/EDIT с content/file URI, с любым
MIME-типом и без MIME-типа. SEND и SEND_MULTIPLE принимают EXTRA_STREAM и ClipData.
Повторяющиеся URI удаляются из списка входящих файлов. Импорт выполняется в рабочем
потоке, имена и расширения сохраняются. Читаемые file URI открываются по исходному
пути; content URI становятся долговечной личной копией, о чём сообщается пользователю.
Входящий файл открывается в своей вкладке, не закрывая несохранённую книгу.

Activity использует singleTask: внешний менеджер передаёт файл уже работающему экрану
через onNewIntent и выводит его на передний план. При singleTop штатный менеджер HONOR
мог создавать вторую NativeActivity в другом task; она закрывалась вместо отображения
книги. GridCraft использует вкладки книг внутри одного Android-экрана.

Русский перевод охватывает названия всех команд движка (отдельный тест), вложенные
меню, диалоги, сводные таблицы, стили и палитры, настройки диаграмм, строку состояния
и поиск команд на русском. Идентификаторы команд, имена формул и пользовательские
данные остаются прежними. Патч перевода — `patches/0002-russian-dialogs.patch`.

Версия: `0.5.0-files-ru.3`, versionCode `16778502`; Android 8+, arm64-v8a.
APK: `gridcraft-0.5.0-arm64-v8a-files-ru3.apk`.
Ключ: локальный `gridcraft-sideload.keystore`, тот же, что у files-ru.2.

## Исходное поведение на планшете

Устройство: HONOR MLA-W09, Android 16. Для воспроизведения была временно установлена
files-ru.1. Без «Доступа ко всем файлам» документы скрывались. После выдачи
разрешения XLSX/CSV/TSV появились, XLTX оставался скрыт фильтром.
Начальная папка «Документы» содержала DOCX, а тестовые таблицы находились в «Загрузках».

Проверка Android resolver старой сборки не находила GridCraft для VIEW с
application/zip и VIEW без MIME. Исправление добавляет недостающие фильтры.

Тестовые файлы созданы в `Download/GridCraft-Test`; пользовательские документы не менялись.

## Итоговая проверка на планшете

- Встроенное окно показывает четыре тестовых документа: XLSX, CSV, TSV и XLTX;
  неподдерживаемый PDF не отображается при включённом фильтре.
- XLSX открывается с текстом «Проверка открытия» в A1 и числом 42 в B1.
  Обычное сохранение обновляет исходный XLSX в общей папке: сохранённый файл выгружен
  обратно и проверен как корректный пакет с xl/styles.xml.
- X-plore: контекстное меню → «Открыть в Системе» → GridCraft; content URI успешно
  импортирован и открыт, отображается русское сообщение о копии файла.
- Штатные «Файлы» HONOR: «Открыть в приложении» → GridCraft → «Только сейчас».
  После исправления singleTask редактор выходит на передний план и показывает данные;
  системная ассоциация файлов по умолчанию не менялась.
- Холодный запуск VIEW с XLSX, ошибочно помеченным application/zip, и повторный VIEW
  с CSV/text/plain проверены отображением данных. Повторный intent доставлен текущей
  Activity. SEND с EXTRA_STREAM тоже открывает CSV в работающем редакторе.
- Android resolver на устройстве: 16/16 случаев VIEW/EDIT/SEND/SEND_MULTIPLE,
  file/content URI, правильный MIME, generic MIME и отсутствие MIME.
- DEX содержит мост доступа и входящих файлов; ACTION_OPEN_DOCUMENT отсутствует.
  Native library и DEX в APK побайтно совпадают с результатами сборки.
- Подписи APK v2/v3 и выравнивание проверены. SHA-256 установленного base.apk
  совпадает с локальным итоговым APK.
